# StageForge show files

A `.stageforge.show.json` file stores a rig, its ordered cue list and the lighting desk as plain UTF-8 JSON. Version 1 can also carry a recorded sequence, camera and volume settings, and the names and positions of sound and screen media. The schema uses JSON Schema Draft 2020-12. [Version 1 schema](../src/schemas/show-v1.schema.json) · [Amber Walk-on example](../public/examples/amber-walk-on.stageforge.show.json)

Version 2 adds per-group optics, independent moving-head looks, per-projector laser settings and LED cabinet grids. The writer selects v1 whenever the rig, cues and entire take fit that schema. [Version 2 schema](../src/schemas/show-v2.schema.json)

Version 3 adds a required `stage` object for editable trusses, speaker hangs, scenery, wall placements and independent secondary-screen events. The primary wall still follows the standard show timeline. The web desk previews its supported fields and preserves the native stage when saving the same show. Starting a separate rig clears that stage. [Version 3 schema](../src/schemas/show-v3.schema.json)

Version 4 adds a required `interchange` block (with optional `stage`) for persistent MVR object UUIDs, synthetic position-bar markers, original manufacturer GDTF references and bounded XML passthrough fragments (up to 8 MiB UTF-8 total) from imported MVR scenes. The writer selects v4 only when `interchange` has data; shows without `interchange` continue to save as v1, v2 or v3, and v1–v3 files remain loadable unchanged. [Version 4 schema](../src/schemas/show-v4.schema.json)

Version 5 is an additive superset (both `stage` and `interchange` optional) that adds optional SMPTE timecode metadata on `timeline`: `frameRate` (`24`, `25`, `29.97` drop-frame, or `30`) and `timecodeOffsetMs` (`0..86399999`, e.g. `3600000` for `01:00:00:00`). The writer selects v5 only when `timeline.frameRate` or `timeline.timecodeOffsetMs` is present. [Version 5 schema](../src/schemas/show-v5.schema.json)

Version 6 is an additive superset that adds optional equipment catalogue metadata on overhead fixtures and floor effects (`catalogId`, `dmxMode`, `dmxChannels`) and LED cabinet presets (`ledWall.cabinets.cabinetId`). Whenever `catalogId` is set on a fixture or floor-FX group, both `dmxMode` and `dmxChannels` are also required so DMX address layout remains deterministic even if catalogue data changes later. The writer selects v6 only when at least one v6 catalogue field is present. [Version 6 schema](../src/schemas/show-v6.schema.json) · [Equipment catalogue](equipment.md)

Version 7 is an additive superset that adds optional rigging and electrical specifications: truss profile (`trussProfileId`), chain hoist rating (`hoistId`), and box-truss hoist point count (`hoistCount`, 2–4 on `box` pods only) on `rig.trussPods[*]`, optional dimmer/power circuit labels (`circuitGroup`, up to 32 ASCII chars) and phase pins (`phase`: `L1`/`L2`/`L3`) on `fixtures[*]` and `floorFx[*]`, and optional `rig.power` (`system`, `feederA`, `pins[]` up to 8 unique department pins). The writer selects v7 only when at least one v7 field is present; all schemas ship with the web reader for offline validation. [Version 7 schema](../src/schemas/show-v7.schema.json) · [Rigging & power](rigging-power.md)

Version 8 is an additive superset that adds optional audio-reactive fixture and control mappings on `look`, `cues[*].state` and `timeline.events[*].look`: `audioMap: { mappings: AudioMapping[] }` (up to 16 mappings). Each mapping binds a live audio feature (`bass`, `mid`, `high`, `energy`, `beat`, `drop`, or a 32-band FFT range `band` with `bands: [lo, hi]` in `0..31`) to a target group (`beam`, `wash`, `blinder`, `strobe`, `ledWall`, `laser`, `haze`) and parameter (`dimmer`, `zoom`, `colorMix`, `strobe`, `speed`, `tilt`, `brightness`, `intensity`, `rotation`, `spread`, plus optional laser `projectorKey`), with `amount` (`-1..1`), envelope `attackMs`/`releaseMs`, `threshold` (`0..1`), and `curve` (`linear`/`square`/`sqrt`). Cross-field rules beyond the JSON Schema (unique mapping IDs, `bands[0] <= bands[1]`, valid `(group, param)` pairs, non-negative `amount` on strobe and laser-speed targets, slow haze envelope bounds `attackMs >= 1000` / `releaseMs >= 2000`, and valid rig laser `projectorKey` existence) are enforced by StageForge's loader (`checkLook` in `src/data/showFile.ts`). Modulation is evaluated live at runtime and never baked into recorded takes or cues. The writer selects v8 only when at least one audio mapping is present; v1–v7 shows remain loadable and writable unchanged. [Version 8 schema](../src/schemas/show-v8.schema.json) · [Audio mappings & Show control](show-control.md#audio-reactive-mappings)

Version 9 adds optional cue `fadeSeconds` and recorded-take `cueFade` descriptors for deterministic preview intensity fades. The writer selects v9 only when one of those fields is present; files that do not use them retain their prior v1–v8 writer selection. [Version 9 schema](../src/schemas/show-v9.schema.json)

Version 10 adds an optional top-level declarative `crowd` layout: deterministic standing or theatre-seat zones, rectangular exclusions, explicit placements, model weights, generator seed, and generator version. The writer selects v10 for human-only generator-v1 crowd data; crowd-free files retain their prior v1–v9 writer selection. Runtime placements are derived and are never serialized. [Version 10 schema](../src/schemas/show-v10.schema.json)

Version 11 extends the crowd model IDs to the built-in StageForge human, original robot and original alien, and adds deterministic generator version 2 for mixed-model placement. Human-only generator-v1 crowds continue to write v10 byte-compatibly; generator-v2 or mixed-model crowds write v11. Model geometry is built in and requires no network access. [Version 11 schema](../src/schemas/show-v11.schema.json)

Version 12 adds the original human variant with separate skin and garment colors and the foxlike audience figure. A show uses v12 when any zone weight or explicit placement names either new model. The original generator-v2 IDs continue to write v11. Both new figures are built in and available offline. [Version 12 schema](../src/schemas/show-v12.schema.json)

Version 13 adds the original monochrome moth and ticket taker. It is selected when a crowd references either model. The figures ship with StageForge and share one render batch when present. Shows with only the earlier crowd model IDs retain their minimum version. [Version 13 schema](../src/schemas/show-v13.schema.json)

Version 14 adds the built-in 1928 film cast. A show uses v14 when a zone weight or a deliberate placement references a new cast model ID. Earlier crowds continue to save at their minimum supported version. [Version 14 schema](../src/schemas/show-v14.schema.json)

Version 15 adds logical DMX universes U3–U16 for Show JSON, Show Bundle and simulated playback. Add or change a universe in Rig Builder and inspect its simulated slots in DMX Monitor. A show uses v15 when its authored patch includes any U3–U16 group. Current physical transports still use logical U1–U2, and pre-flight blocks arming while the authored patch uses an extended universe. A StageForge MVR carries those logical addresses in its independent native payload v2. [Version 15 schema](../src/schemas/show-v15.schema.json)

The local design keeps the current rig, stage layout, wall cues and authored crowd, with one previous design available in Show files. Opening a Show or example leaves that local design available until you edit or choose **Save as local design**. Use **Restore saved design** or **Restore previous design** to return to it and relink any named media. Save Show JSON or a Show Bundle for the complete desk and take. Standalone Rig JSON remains available for U1–U2 designs.

## Opening the examples

Choose **Files → Open Amber Walk-on example**, then **Show cues → Replay take**. The example starts a club rig in blackout. Its first cue follows after 2.5 seconds and brings four moving heads up in amber. The second cue holds until the operator advances. The six-second recording starts the built-in score, starts the main-wall video at the reveal, pauses the wall at five seconds and pauses the score at six seconds. The app bundles the [amber screen clip](../public/examples/amber-clouds.mp4). When opening the JSON directly on another machine, select the matching clip in **Files → Relink media files**.

**Files → Open Split Rig rehearsal** opens a 16-second performance. Two washes focus on the drum riser while two beams sweep independently. The final reveal uses two laser projectors with five and seventeen rays. Both examples share the bundled amber video. [Split Rig show](../public/examples/split-rig.stageforge.show.json)

**Files → Open Steamboat Willie example** places the 1928 cast beside an audience of original StageForge characters. Open Stage Designer to edit individual placements or use the full-cast preset. All character geometry ships with the app. [Steamboat Willie show](../public/examples/steamboat-willie.stageforge.show.json)

## Reading and writing a show

| Field | Meaning |
| --- | --- |
| `$schema` | The public schema URL ending in `show-v1.schema.json` through `show-v15.schema.json`, matching the version. |
| `format`, `version` | The string `"stageforge-show"` and an integer from `1` through `14`. |
| `stage` | Required in v3, optional in v4–v15. Wall IDs connect the native stage geometry to its timed secondary-screen media events. Local media references contain filenames. |
| `interchange` | Required in v4, optional in v5–v15. Stores persistent MVR object UUIDs (`mvr.uuids`), importer-synthesized position-bar IDs (`mvr.synthetic`), imported GDTF spec/mode references (`mvr.fixtureSpecs`) and bounded unrecognised MVR XML passthrough fragments (`mvr.passthrough`: `userData`, `auxData`, `sceneNodes`, `objectExtras`, capped at 8 MiB UTF-8 total with DTDs and processing instructions rejected). |
| `rig` | Stage dimensions and venue, optional platforms and scenic props, trusses with their fixtures, floor effects, sound system and LED wall (in v6: `catalogId`/`dmxMode`/`dmxChannels`, `cabinetId`; in v7: `trussProfileId`/`hoistId`/`hoistCount`, `circuitGroup`/`phase`, and `rig.power`). Positions and lengths use metres. |
| `cues` | Array in playback order. Each cue has a unique `id`, a display `name`, `tag`, hex `accent` and a partial desk `state`. Optional `screen` sets the main-wall media. |
| `look`, `activeCueId` | Complete current desk settings and the current cue ID, or `null`. Desk changes made after calling a cue belong in `look`. |
| `controls` | Optional named camera preset and music volume from zero to one. |
| `media` | Optional current transport references for both music and the main LED wall. |
| `timeline` | Optional recording with integer `durationMs`, an ordered `events` array, and (in v5) optional SMPTE `frameRate` (`24`, `25`, `29.97`, `30`) and `timecodeOffsetMs` (`0..86399999`). |

Cue states apply as top-level changes. For example, `{"masterDimmer":0.72}` changes just the master, while a cue that changes `led` supplies the whole LED object. `fadeSeconds` (show v9) is a bounded 0–3,600 second destination-cue fade for preview beam and wash intensity; zero or omission is a cut. The authored destination and all physical output change immediately. Use `followSeconds` for a timed advance after a cue is called. Follow starts when the cue fires, independently of its fade, and may interrupt it. Valid follow values are greater than zero and at most 3,600. Omit it for manual GO.

In v2, `movingGroups.beam` and `movingGroups.wash` override selected movement and color fields. Omitted fields use the shared look, and `movingGroups: {}` explicitly restores both groups to it. A laser appearance can include `patternSegments`, `colorA` and `colorB`. The keys of `laser.projectors` are JSON-encoded triples of truss ID (null for floor equipment), fixture-group ID and one-based unit number. A patch address can change without moving the settings to another projector.

A nonempty recording begins with a complete snapshot at `atMs: 0`, including `look`, `cueId`, `camera`, `volume`, `bump`, `music` and `screen`. Subsequent events contain `atMs` and the fields that changed. In v9, a cue event can carry `cueFade` with its authored `from`, destination `to`, and duration; this is enough to restore or seek the preview transition deterministically without per-frame events. The six bump flags represent the pressed state of the blinder, strobe, CO₂, smoke, laser and motor-drop controls. Event times must be nonnegative, nondecreasing integers no later than `durationMs`. Apply simultaneous events in file order. Event cue IDs are historical and may survive the deletion of a cue. Replay the recorded look in those events.

A music reference stores its kind (`demo`, `file`, `live` or `none`), display name and playing state. Audio files may include a position in seconds. The built-in score may include `demoStep`, measured in sixteenth notes from zero to 1,024, including fractional positions. Screen media uses `target: "main-led"`, kind `video`, `image` or `none`, its name, playing state and optional position in seconds. Files are identified by basename. Reopening the show on another machine requires access to matching local files. The built-in score travels with the app.

The reader validates the current cue ID, focus marks and motor targets against the show. Within the rig, list IDs are unique, motor limits must be ordered, adjacent truss vertices must be at least 0.25 metres apart and the fixture count may reach 1,024 across the two universes. The exporter clears temporary media URLs and omits session-only data. Existing rig-only `.stageforge.json` files keep their original format.

## Reuse and interoperability

The file format, schema, example show and reference reader are available under the repository's MIT license. Projects are ordinary JSON and can be created, edited and validated offline. The schema URL identifies the format; the StageForge reader uses a bundled copy. Your own show files and media retain the licenses you choose for them. To review a show or bundle without editing or starting live output, open it in the [Read-only Pitch Viewer](viewer.md) (`?view` or **Files → Open in viewer…**). [Reference implementation](../src/data/showFile.ts) · [License](../LICENSE)

DXF carries a plan drawing, glTF 2.0 GLB carries a static stage scene, and CSV lists the simulated channel patch. Use the show JSON for the timed performance. StageForge records desk changes, named camera selections, effect-button states and media transport. The timeline does not include live microphone samples, mouse orbit trajectories, design-edit history, or frame-by-frame DMX universe output. [Khronos glTF](https://www.khronos.org/gltf/) · [Unreal Engine glTF import](https://dev.epicgames.com/documentation/en-us/unreal-engine/importing-gltf-files-into-unreal-engine)
